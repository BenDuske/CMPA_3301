# My Experience Learning Markdown

Working through the Markdown tutorial was a quick win. I already document controls work and code daily, so the idea of **separating content from formatting** clicked immediately — Markdown is just a clean, portable way to do what I already care about: making notes anyone can read.

What stood out most:

- Headers are just `#` symbols — one for a title, more for subsections.
- You wrap text in `*asterisks*` for *italics* and `**double asterisks**` for **bold**.
- Lists are simple: a `-` for bullets or `1.` for numbered items, kept *consistent*.
- A link is `[text](url)` — tidy and readable even in raw form.

The part I appreciate as someone from a hardware and automation background is that a Markdown file is **just plain text**. No proprietary format, no hidden formatting to corrupt, and it reads fine whether it's rendered or not. That's the same reliability mindset I bring to critical systems: keep it simple, keep it portable, make it work everywhere.

I'm comfortable writing this file by hand now, and I'll be using it for every charter, README, and project doc this semester.
