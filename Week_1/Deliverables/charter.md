## Project Name

**Benjamin Duske — Professional Portfolio Website**

A clean, responsive personal website that introduces who I am, showcases my background in controls engineering and AI, and serves as a living portfolio piece I can keep using after this course and point employers to.

## Course Goals

By the end of this semester, I want to master the following, concretely:

1. **Write clean, semantic HTML** — structure a multi-section page using the correct elements (`header`, `nav`, `main`, `section`, `footer`) instead of generic `div`s, so the markup is readable and accessible.
2. **Style a responsive layout with CSS** — build a navigation menu and content layout that uses the box model deliberately and adapts to different screen sizes, with a color palette I choose on purpose.
3. **Run a real GitHub workflow** — manage the whole project in a public repository using commits, branches, and pull requests, so the site's history reads like a professional project, not just saved files.

## Potential Challenges

Being honest about what could slow me down:

- **Time balance.** I work full-time as Lead Controls Operator at a hospital and have a family of six. Coursework competes with a demanding on-call schedule.
- **CSS layout specifically.** I'm comfortable with logic and systems, but visual design and getting a layout to *look* right (spacing, alignment, responsiveness) is less familiar territory for me than backend/controls work.
- **Git branching discipline.** I use Git, but doing the full branch → pull-request → merge cadence *properly* and consistently — rather than committing straight to main — is a habit I still need to build.

## Mitigation Strategy

For each challenge above, here's how I'll handle it:

- **Time balance → block and protect schedule.** I'll treat each week's deadlines as fixed appointments on my calendar (already added, with reminders the day before) and front-load coursework early in the week rather than racing the Sunday cutoff.
- **CSS layout → learn by small, repeated reps.** I'll lean on the Week 4 "Find Your Palette" and "Box Model in Practice" exercises as building blocks, and prototype layouts in small pieces (one section at a time) instead of trying to style the whole page at once.
- **Git discipline → one branch per feature.** I'll make a rule for myself: no direct commits to `main`. Every change gets its own branch and a pull request, even working solo, so the workflow becomes muscle memory the way the course intends.
